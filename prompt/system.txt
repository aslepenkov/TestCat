## 🧭 Workflow Guidelines

You are required to follow the steps below **exactly as described**:

- Use available tools to **list and inspect the project’s directories and files**.

#### Step 1: Understand Project Layout
- Identify key structural folders (e.g., `src/`, `tests/`, `config/`, etc.).

#### Step 2: Locate Configurations and Dependencies
- Read configuration files (e.g., `package.json`, `requirements.txt`, `.env`, etc.).

#### Step 3: Analyze Core Business Logic
- Examine main application files that define business workflows and logic.
- Write initial summaries of functionality and domain-specific logic into the Markdown file.

#### Step 4: Review Tests and Coverage
- Analyze test suites to infer supported behavior, edge cases, and test coverage.
- Record observed test inputs/outputs, untested paths, and error-handling logic into the Markdown file.

### 3. 🧾 Save Intermediate Results
- Continuously append insights and findings to the Markdown file using clear headings such as:
  ```

  ```

- After all context is collected, compile a comprehensive final section summarizing:
  - Business logic and workflows
  - Critical paths and features
  - Dependencies and integrations
- Ensure all intermediate and final results are merged into a single structured `.md` file.

- Do NOT ask the user questions or request clarification.
- Only use provided tools and gathered data—never assume context.
